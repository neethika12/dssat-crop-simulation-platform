How This Works (plain-English guide)

What is this page?

This is a tool for testing whether a crop-growth computer model predicts real harvests accurately — and for automatically tuning that model to fit better. It's built on top of DSSAT (Decision Support System for Agrotechnology Transfer), a crop simulation program that's been developed and used by agricultural researchers worldwide for decades to predict how a crop will grow given its soil, weather, and how it's managed (planting date, fertilizer, irrigation, etc.).

Crucially, this isn't a simplified re-creation of DSSAT — it runs the actual DSSAT program (compiled from its official source code) and real historical field-experiment data. Nothing here is faked or approximated for demo purposes.

What data is this using?

The dropdown at the top lists real field experiments from DSSAT's own public example dataset — actual maize trials run by researchers in places like Gainesville (Florida), Brazil, Spain, and Ghana, going back to the 1980s and 90s. Each one recorded real measurements: how much grain was harvested, how tall the plants grew, etc., under different real-world conditions (irrigated vs. rainfed, high vs. low nitrogen, etc.).

What does "Run Validation" do?

It runs the real DSSAT model using that experiment's actual weather, soil, and management data, and asks it to predict the yield for each treatment. Then it compares that prediction to what was actually measured in the real field trial decades ago. The chart shows both side by side — green bars are the model's guess, orange bars are the real harvest.

What do RMSE, nRMSE, Willmott's d, and R² mean?

These are four different ways of scoring "how close was the model's guess to reality?" — think of them like different report-card grades for the same test:

  • RMSE (Root Mean Squared Error) — the average size of the model's mistake, in the same units as the crop yield (kg per hectare). Smaller is better. An RMSE of 970 means the model's predictions were typically off by about 970 kg/ha.
  • nRMSE (normalized RMSE) — the same idea, but as a percentage of the average real yield, so you can compare error size across very different experiments. Under ~15% is generally considered a good fit for crop models.
  • Willmott's d — a score from 0 to 1 measuring overall agreement between predicted and real values. 1.0 would be a perfect match; above 0.9 is considered strong agreement.
  • R² (R-squared) — from 0 to 1, how well the model's predictions track the pattern of the real results (e.g. correctly predicting which treatments yield more or less than others), even if the exact numbers are a bit off.

What does "Automated Calibration" do?

Every crop variety (cultivar) has internal "genetic coefficients" in DSSAT — numbers describing things like how fast it matures or how much it fills grain. Nobody knows the exact right numbers for a given variety in advance; they're estimated and refined by comparing model predictions to real field data, then adjusting.

This tool automates that adjustment process: it tries many different combinations of those coefficients (using an algorithm called differential evolution — think of it as an organized trial-and-error search, not guesswork), re-runs the real DSSAT model each time, and keeps the combination that gets closest to the real measured yields. The chart shows the best error found getting smaller as it searches.

Can I test this with my own data?

Yes — that's what the "Test With Your Own Data" section on the main page is for. Here's what you need:

  • A FileX — DSSAT's standard experiment description file (extension like .MZX for maize, .SBX for soybean, .WHX for wheat, etc.). This describes the field, planting details, weather station, soil, and treatments. If you've used DSSAT's own tools (like XBuild) to set up an experiment, this is the file it produces.
  • An observed-data file (optional) — DSSAT's summary file of what was actually measured (extension like .MZA), so the tool can compute validation statistics. Without it, you'll still get the simulated predictions, just nothing to compare them against.
  • A time-series observed-data file (.xxT) is also accepted if you have one (e.g. leaf area or biomass measured over the season, not just final yield).

Scope note: "Run Validation" works for any crop DSSAT supports, since it runs the real model directly on whatever you upload. "Automated Calibration," however, is currently wired up only for the built-in reference experiments (it needs to know which cultivar file and coefficients to adjust for a given crop) — happy to extend it to a specific crop/cultivar on request.

If DSSAT can't run your file, you'll see the model's own error message rather than a generic failure — that's intentional, so a real error (e.g. a missing soil profile) is diagnosable.

A note on hosting

This runs on free-tier hosting, which is slower and can idle down after inactivity (the first request after a while may take ~30-60s to wake back up — that's normal, not a bug).
